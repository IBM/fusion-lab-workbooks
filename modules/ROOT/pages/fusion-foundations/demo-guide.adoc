= Platform Modernization with IBM Fusion: Demo Guide
:navtitle: Fusion Demo Guide

== Introduction

IBM Fusion is a container-native storage and data management platform designed specifically for Red Hat OpenShift Container Platform. It delivers essential data services—including persistent storage, backup and disaster recovery, data cataloging, and hybrid multi-cloud mobility—all managed seamlessly through OpenShift.

=== About this demo

This hands-on demo workbook guides you through installing, configuring, and exploring key capabilities of IBM Fusion:

* Installing the IBM Fusion Operator from the Software Catalog
* Exploring the IBM Fusion administration dashboard and services
* Configuring persistent storage with **Fusion Data Foundation (FDF)** and remote **IBM Storage Scale**
* Protecting containerized workloads with **Backup & Restore**
* Managing data services, storage classes, and disaster recovery workflows

=== Prerequisites and TechZone Environment

Before starting this demo, ensure you have provisioned an IBM Fusion lab environment in IBM Technology Zone (TechZone).

[NOTE]
====
For detailed step-by-step instructions on creating an IBMid and requesting your TechZone environment, see the xref:getting-started/tz-quick-start.adoc[TechZone Quick Start Guide].
====

== Demonstration Scope

=== Hybrid Multi-Cloud Container Workloads

Most enterprise organizations operate across hybrid multi-cloud environments. Containers drive the evolution from siloed, on-premises applications to portable, infrastructure-independent workloads.

As applications become containerized and distributed, modern data services must address key operational challenges:

* Dynamic storage provisioning across heterogeneous backends
* Application-aware data protection and snapshot management
* High availability and business continuity across clusters
* Policy-based data governance and metadata cataloging

IBM Fusion provides a unified control plane and containerized data engine directly integrated into OpenShift to address these challenges.

=== Demonstration Journey

This demonstration covers the following milestones:

. **Accessing the Cluster:** Connecting via the OpenShift Web Console and Bastion CLI (`oc`).
. **Operator Installation:** Deploying the IBM Fusion Operator on OpenShift.
. **Storage Provisioning:**
  * Setting up local software-defined storage using **Fusion Data Foundation (FDF)**.
  * Mounting remote storage via **IBM Storage Scale**.
. **Data Protection:** Installing the **Backup & Restore** service and safeguarding sample stateful applications.
. **Administration & Monitoring:** Reviewing alerts, cluster events, Call Home, and service health.

== Demonstration Infrastructure

=== Platform Architecture

The demonstration environment is deployed on an enterprise OpenShift Container Platform (OCP) cluster supported by dedicated storage infrastructure:

* **OpenShift Cluster (6+ VMs):**
  ** 3 Control Plane (Master) nodes running Red Hat Enterprise Linux CoreOS (RHCOS)
  ** 3 Infra nodes (`itz-++*++-infra-++*++`) dedicated to Fusion Data Foundation (local NVMe/SSD storage)
  ** 3 Worker nodes (`itz-++*++-worker-++*++`) for running demo applications and container workloads
* **IBM Storage Scale Node (1 VM):** Provides an external remote Storage Scale cluster and filesystem mount.
* **IBM Storage Ceph / S3 Storage (1 VM):** Provides S3-compatible object storage targets for backup locations.
* **Bastion Host:** Provides external SSH access with pre-configured tools (`oc`, `kubectl`, `helm`, `curl`).

[NOTE]
====
You do not need to access the underlying OpenShift node VMs directly. All administrative tasks are performed via the **OpenShift Web Console** or the OpenShift CLI (`oc`) — either from the Bastion host over SSH or from your local laptop.
====

=== Environment Access & Credentials

All endpoints and credentials are found in the **Outputs** section of your TechZone reservation page. Navigate to https://techzone.ibm.com/my/requests[My requests^], open your reservation, and expand the environment row to reveal the Outputs panel shown below.

image::tz-fusion-reservation.png[TechZone reservation outputs panel, link=self]

The following table summarises the fields you will use throughout the labs:

[cols="1,2",options="header"]
|===
| Field | Description
| **API URL** | OpenShift API endpoint used for `oc login` and kubeconfig
| **OCP Console** | OpenShift Web Console URL — open directly in your browser
| **Cluster Admin Username** | `kubeadmin`
| **Cluster Admin Password** | Hidden field — click the eye icon to reveal, or the copy icon to copy
| **Bastion SSH connection** | Pre-built SSH command — copy and paste directly into your terminal
| **Bastion Username** | `itzuser`
| **Bastion Password** | Hidden field — required only for `sudo` commands on the Bastion, not for SSH login
| **Download kubeconfig** | btn:[Download] — saves as `conf_kubeconfig_download.conf`
| **The private SSH key** | btn:[Download] — required to authenticate your SSH connection to the Bastion
| **VM Remote Console** | Browser-based VNC access to the underlying cluster VMs
| **Environment ID** | Your unique 24-character environment identifier
|===

IMPORTANT: The Bastion host uses **key-based SSH authentication only** on port 10022. Password authentication is disabled on that port. You must download the private SSH key before attempting to connect.

== Accessing the Environment

Before starting the lab exercises, ensure you can connect to your cluster. See xref:getting-started/access.adoc[Accessing the Environment] for step-by-step instructions covering the OpenShift Web Console, Bastion SSH (macOS, Linux, and Windows), and the local `oc` CLI.

Once connected, verify your access from the Bastion or your local terminal:

[source,shell]
----
oc whoami
oc get nodes
----

`oc whoami` should return `kubeadmin` and all cluster nodes should be in `Ready` state before proceeding.
